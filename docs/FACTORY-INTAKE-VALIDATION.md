## Acceptance cases

Repeated collection and concurrent exact retries retain one candidate identity.
Every complete read adds immutable observations; failed/incomplete reads retain
older evidence and block its use until complete coverage returns. Tests exercise
HTTP failure/403, HTML, timeout, malformed issue/list, oversized response,
truncated/repeated pagination, aggregate byte limits and a whole-collection
deadline across individually responsive pages.

Changed issue content blocks filing before recollection and revokes old
verification. Source edits during a read reject its result before mutation.
Changed provider settings require explicit source save and fresh coverage.
Disabled sources, stale revisions, unknown fields/actions, empty rationale and
missing/completed filing columns fail visibly. Nullable author/body evidence is
retained without invented values or invalid empty rich-text nodes.

Two rechecks of one stable finding do not establish recurrence. Distinct findings
across two tasks form one candidate with original IDs, code context and latest
rechecks. Further rounds retain that identity. Withdrawal of an occurrence makes
old verification unusable without losing captured evidence.

Verification creates no task. Concurrent exact filing creates one root backlog
task with source provenance and no agent/pipeline run. Existing exact normalized
titles require explicit linking, which changes no existing task fields. Deleted
filed tasks retain their source link and cannot be silently recreated. Dismissal
survives recollection. Native restart preserves the full intake library and
decisions; an interrupted collection remains unavailable and is never replayed.
Project deletion removes the intake records transactionally through public APIs.

changes, retry state after a successful mutation followed by refresh failure,
empty rich-text evidence nodes, nullable provider authors/bodies, collection-wide
bounds, form styling and light-theme contrast. GitHub transport/authentication is
shared with delivery instead of creating a second credential path. The unconfigured empty preview makes no claim of completed coverage;
only an actual collection receipt establishes a successful empty read. Source domain
rules protect configuration and candidate transitions; application use cases
coordinate reads and native transactions through IWorkspaceStore. New literals
were traced to configured deployment limits, GitHub protocol limits, domain
state/category identifiers or explicit fixture inputs.

The feature performs manual source-backed triage. It does not prove arbitrary
issue claims, perform fuzzy semantic deduplication, automatically file work or
start implementation. Operators must judge reproduction and scope. External
GitHub content may change after an observation; immediate re-reads and immutable
receipts make that boundary explicit.
