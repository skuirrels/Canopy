# Canopy v0.2.0 — Software Factory configuration

Canopy now supports reusable Software Factory pipelines alongside its existing
planning views. Configure stages and skills, publish an immutable version, and
attach it to a task with explicit overrides. Configuration never starts work or
changes a task's status.

## Included

- Versioned pipeline drafts, configured templates, structural validation and
  transactional native DuckDB persistence.
- A grouped React Flow designer and an equivalent list/settings editor, with
  custom stages, dependency checks, typed commands and skill-source references.
- Explicit publication, read-only version history, archiving, task attachments
  and version adoption. New publications never silently upgrade task attachments.
- Browser recovery with revision conflicts, keyboard connections and responsive
  editing. Canvas arrangement and camera settings remain separate from pipeline
  semantics and the task Mind Map.
- A review fix for configured template IDs equal to `custom`: template choices
  and the custom-pipeline action now have distinct UI values, preserving the
  exact configured ID, definition and provenance in the API request.

The configuration foundation and designer were delivered in PRs
[#10](https://github.com/skuirrels/Canopy/pull/10) and
[#11](https://github.com/skuirrels/Canopy/pull/11). See

## Install and upgrade

This is a source release. Use the GitHub tag/source archives with .NET 10 and
Node.js 22.12+ (or a newer supported version), following the existing README:

```sh
git clone --branch v0.2.0 https://github.com/skuirrels/Canopy.git
cd Canopy
make prod
```

For an existing installation, stop the backend and back up its configured
DuckDB database before upgrading. Preserve deployment configuration and the
configured template catalogue, update to this tag, then run `make prod`.
Startup applies the repository's existing database migrations. This release
preparation adds no migrations or API-contract changes. Publishing this release
does not restart or deploy a running installation.

## Scope

The application remains a single-user, single-backend-process native DuckDB
deployment. Pipeline execution, installed-skill discovery and runtime-readiness
certification remain later work. Existing explicit Agents actions stay
independent. Template selection is not execution, and recorded skill references
are labelled unverified.

## Verification

The release review rebuilt both Debug and Release backends and the production
frontend. It reran 93 client tests, 50 factory API/DuckDB checks, 57 planning API
checks, 18 linked-specification checks, 6 MCP tests and the maintained Factory
Postman collection (12 requests / 20 assertions). Browser checks use a temporary
Release backend and database, including a separate configured catalogue with
template ID `custom`; no live workspace data is used.
All 40 designer/extended/restart checks passed again, as did the targeted
template-ID browser checks and that pipeline's restart-persistence comparison.

designer interaction coverage and the additional release-review evidence.
